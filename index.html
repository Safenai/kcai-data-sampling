    Available on PyPI

    Install individual packages based on your needs:

    Package Description PyPI
    kcai-data-sampling-core Transformation interface, configuration models, registries and runner
    kcai-data-sampling-images Procedural family: model-free image transformations
    kcai-data-sampling-albumentation Curated image-robustness catalogue (albumentations)
    kcai-data-sampling-lama Generative inpainting (LaMa) transformation and tool-model plugin
    kcai-data-sampling-fgsm Adversarial (FGSM) transformation and target-model support
    kcai-data-sampling-job Pipeline orchestration and IO plugins

    Note: The kcai-data-sampling package is the CLI wrapper.

    What is KCAI Sampling?

    KCAI Data-Sampling is an open-source Python library that helps you create and control the data your models are trained and evaluated on. Whether you're testing model robustness, building contextual validation sets, or stress-testing against adversarial inputs, it lets you generate targeted variants of a real dataset (procedural transforms, generative completions, adversarial samples) and keep a reproducible record of how each was produced.

    Think of it as a controlled data generator — every sample comes with its recipe, so experiments can be reproduced, compared, and audited.

    Why use it

    • Configuration-driven data selection: Run transformations on specific data selections via a configuration (no need to write ad-hoc scripts per experiment).
    • Reproducible recipes: Every run produces a recipe in the output, making experiments traceable and reproducible.
    • Three composable families: Procedural, generative, and adversarial transformations are all supported in a single tool, enabling complex data science scenarios that combine two or more transformation families.
    • Unified workflow: Switch between robustness testing and controlled-context generation without changing tools.
    • Extensible plugin model: New transformation families/packages can be integrated without redesigning the orchestration/config model. The system supports input and output plugins, allowing custom data sources and destinations to be added.
    • Contract-driven outputs: Standardized outputs make it easier to compare results across transformation families and runs.

    Installation

    pip install "kcai-data-sampling[all]"

    Select only the extras you need:

    pip install "kcai-data-sampling[core,images,job]"

    [all] pulls torch, which on Linux defaults to a CUDA build. On a machine without an NVIDIA GPU, ask for the CPU wheel instead:

    pip install "kcai-data-sampling[all]" --extra-index-url https://download.pytorch.org/whl/cpu

    For development (editable install with all extras and dev tools):

    git clone https://github.com/Safenai/kcai-data-sampling.git
cd kcai-data-sampling
uv sync --all-extras

    Quick start (CLI)

    kcai-data-sampling process -p examples/config/walkthrough-procedural.yaml

    Available subcommands: version, list, process. process requires the [job] extra to be installed. For programmatic use, see the quickstart.

    Workspace structure

    kcai-data-sampling/
├── packages/          # seven member packages (core, images, albumentation, lama, fgsm, job, cli)
├── examples/          # configs, notebooks, sample data
├── docs/              # documentation (quickstart, terminology, usages, benchmark, ...)
├── benchmark/         # benchmark harness (s1/s2/s3)
├── scripts/           # helper scripts (fetch sample data, code quality, ...)
├── tests/             # unit and e2e tests
└── noxfile.py         # lint, type_check, test, coverage sessions

    Running the walkthrough notebook

    The walkthrough runs the procedural job, LaMa inpainting and FGSM on real comma10k frames. Its notebook, configs and data all live in the repository rather than in the wheel, so if you have not cloned it yet:

    git clone https://github.com/Safenai/kcai-data-sampling.git
cd kcai-data-sampling

    If you have not been through the quickstart, set up an environment first:

    python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate

    Then install the all extra — the union of everything the notebook touches — and fetch the ten sample frames:

    pip install "kcai-data-sampling[all]"
python scripts/fetch_comma10k_sample.py

    [all] pulls torch, which on Linux defaults to a CUDA build. On a machine without an NVIDIA GPU, ask for the CPU wheel instead:

    pip install "kcai-data-sampling[all]" --extra-index-url https://download.pytorch.org/whl/cpu

    Open examples/notebooks/walkthrough.ipynb in Jupyter (JupyterLab or VS Code) and pick the interpreter of the environment you activated as the kernel. Run it top to bottom — the setup cell re-chdirs to the repository root and reads examples/config/walkthrough-procedural.yaml, so it works regardless of the launch directory. Generated files are left under examples/outputs/.

    Companion tool

    dqm-ml — a "health check for your data". Use it to measure the diversity, representativeness, or domain gap of a dataset before deciding what to sample or augment. Identify which contexts or features are under-covered, then target those gaps with kcai-sampling. Install with pip install "dqm-ml[all]".
