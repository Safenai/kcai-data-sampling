    kcai-data-sampling-albumentation

    Albumentations adapters for the data-sampling pipeline. The package provides a unary image transformation catalogue (aliased under kcai_data_sampling_albumentations.transforms) built from a curated allowlist of Albumentations classes, with automatic schema extraction, dataclass-based configs, clipping/backpressure, and integration with the Output contract.

    Quick start

    Install

    pip install kcai-data-sampling-albumentation

    Run the walkthrough

    From the repository root, use the walkthrough configuration (examples live in the repo):

    python -m kcai_data_sampling.cli run examples/configs/walkthrough_albumentations.yaml

    Or via the published index flow (if using the packaging test helpers), ensure the package is installed in the environment. The walkthrough reads the sample data under examples/data/woodscape_sample/ and writes outputs under examples/out/walkthrough_albumentations/ with a recipe and ledger.

    What this package does

    • Curated catalogue: A fixed allowlist of Albumentations transforms exposed as unary image transforms with consistent naming and config schemas.
    • Schema-driven configs: Dataclasses and JSON-schema generation for transform parameters; unknown or disallowed parameters are rejected.
    • Geometry-safe handling: Transforms that change geometry are tagged (resize_back, crop_back) so the pipeline can track size semantics; the contract remains unary image-only (no batch-wise structural assumptions).
    • Robust execution: Clipping to valid ranges, dtype handling, and integration with the pipeline's Output (deterministic ids, recipe emission).
    • Discoverable: Transforms are registered under kcai_data_sampling_albumentations.transforms and surfaced by the plugin system.

    Scope

    • The filters are based on the main usage scenarios
    • In this version, only classification is integrated. detection and segmentation (bbox, mask, ... supports) will be added in a future release.

    Application probability (p)

    Every catalogue entry inherits a shared p parameter: the probability the transform is actually applied to a given sample. Default is 1.0 (always apply) — deliberately not upstream's 0.5, so a sampling entry never silently emits identity outputs mislabeled as transformed. p can be fixed or swept like any other parameter.

    transformations:
  - name: blur
    type: gaussian_blur
    seed: 11
    p: 0.5                      # apply to half the samples
    sigma_limit: [0.5, 3.0]
  - name: contrast
    type: random_brightness_contrast
    seed: 42
    p:                          # sweep probability across variants
      range: [0.25, 1.0]
      samples: 3
      mode: even
    brightness_limit: [0.1, 0.5]
    contrast_limit: [-0.2, 0.2]

    p is part of the resolved parameters, so it feeds the sample id and the replay contract. All entries also accept p; it is omitted from the per-entry parameter lists below for brevity.

    Catalogue

    The catalogue is the allowlist (see Scope above). Each family is represented: geometry/dihedral, blur, noise, color/tone, occlusion/dropout, weather and compression.

    The package ships the catalogue, not the examples: the walkthrough config and the sample data live in the repository (see Run the walkthrough above).
